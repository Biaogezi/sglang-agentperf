# 简历与项目陈述

数据对应 [最终实验报告](FINAL_REPORT.zh-CN.md)。仅使用实际跑过的版本、硬件与负载；不要删掉
“A10 / W8A8 / 短 prefill / 同配置对照”等限定词。长输出、并发和多轮结果单独报告，不拼成
一个所谓全场景加速比。

## 简历版

**SGLang-AgentPerf｜基于 SGLang 的量化推理性能分析与算子优化**

- 基于 SGLang v0.5.19 搭建可复现实验与 profiling 流程，固定模型/容器版本，比较 Qwen3-8B
  的 FP16、W8A8、AWQ 路径，结合 TTFT、TPOT、吞吐、显存与质量回归分析阶段性瓶颈。
- 针对 A10 短 prefill 实现形状感知 Triton INT8 GEMM，接入原生 W8A8 与 compressed-tensors
  调用路径，支持布局/硬件守卫、CUTLASS 回退及有界 JIT 特化；在相同低延迟调度配置下，
  128-token 输入、单 token 输出、并发 1 场景吞吐提升 **13.15%**，p99 TTFT 降低 **11.32%**。
- 建立算子正确性、实际执行 trace、交替 A/B 与质量证据链；最终短 prefill 三轮共 2,880 请求
  全部完成、配对输出一致，8,128-token 同权重 NLL 差约 **8.5×10⁻⁷**；公开补丁、测试与证据哈希。

项目地址：[Biaogezi/sglang-agentperf](https://github.com/Biaogezi/sglang-agentperf)。

## 一段话版

基于真实 SGLang 引擎开展 Qwen3-8B 量化推理优化，通过分阶段 profiling 定位 A10 上 INT8
GEMM 热点，实现带硬件/形状守卫与回退的 Triton 算子，处理原生量化调用兼容及 JIT 变体膨胀。
在同配置短 prefill 对照中实现 13.15% 吞吐提升，并以重复 A/B、GPU 执行轨迹、算子正确性和
模型质量回归验证收益；同时保留量化质量退化和无效优化的负结果，形成可复现开源实验项目。

## 面试开场（约一分钟）

“我没有再写一个迷你推理引擎，而是在实际 SGLang 上做二次开发。先比较 FP16、W8A8 和 AWQ，
发现 decode 与 prefill 的性能排序不同；再用 trace 看到 INT8 GEMM 占主要计算时间。我对 A10
和 Qwen3 的具体形状扫描 tile，写了一个保守分派的 Triton GEMM，并保留 CUTLASS 回退。

项目最重要的结果是，在同样关闭 overlap 的低并发 128-token prefill 场景，相比相同代码开关
关闭的基线，吞吐从 4144 到 4689 input tok/s，提升约 13.2%。我没有把它说成所有 agent 请求
都加速。过程中也发现过开关没有真正生效、输入重新分词改变形状、小质量集误判 AWQ 等问题，
最后补齐了实际 kernel trace、固定 token 输入、扩大质量集和原始证据校验。”

## 被追问时必须主动说明

1. 自定义 GEMM 是已校准量化权重的执行优化，不是自己完成 AWQ/GPTQ/SmoothQuant 校准。
2. 13.15% 是端到端服务负载的输入吞吐增益，但该负载是形状控制实验，不是生产流量。
3. 两边均使用已有 `--disable-overlap-schedule`；不能把该配置收益归到自写 kernel。
4. 40 条输出一致不等于 40/40 题正确。严格算术格式 0/16 是输出格式未遵循的结果，
   并不表示 16 题都算错；不能为了让分数好看而放宽已经固定的评分规则。
5. 默认不开新路径；没有上游 PR 合并、A100 双卡或国产 NPU 适配成果。
6. 不能承诺全局最优。说明自己的搜索范围、对照、失败方案和剩余热点，比承诺“最优解”可信。
